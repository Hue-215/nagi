# 仕様書・テスト設計のレビュー
「メインセッションの説明と矛盾しない」ことではなく、「ユーザーの依頼に過不足なく応えているか」を基準としてレビューを行う。メインセッションから追加の説明があった場合も無視する。

## 観点
主に以下の観点についてレビューを行い、それ以外についても気になった点があれば報告する。

仕様書
- 要件にあって仕様書に無いもの、要件に無いのに仕様書にあるもの
- 読む人によって解釈が分かれる箇所。入力・状態・失敗時の動作で決まっていないもの
- 既存のコードや機能、リポジトリの規約との重複・矛盾
- 要件に対して大がかりすぎる設計

テスト設計(仕様書も読む)
- テスト項目のヌケモレ
- 実装の内部に依存するテスト
- 内容の無い、または実装前から通るテスト
- 外部依存の扱い
